# 开发记录

## 当前实现方案

角色与悠悠球均使用 Unity 2D 物理。职责拆为 `PlayerMovement`、`YoyoController`、`YoyoProjectile`、`BulletTimeController`、`PrototypeHUD`、`PrototypeReset` 和 `CameraFollow2D`。核心数值集中在 `YoyoTuning` ScriptableObject，避免散落 magic number。

场景和 UI 由 `PhaseOneSceneBuilder` 在编辑期生成并序列化到场景。运行时脚本只更新已有 UI 的数值、方向和显隐，不创建 Canvas、Text、Slider 或 Image。

## 重要技术决策

- 使用旧输入接口读取水平轴和鼠标，减少第一阶段输入配置资产的复杂度。
- 不提供跳跃或任何直接向上冲量。
- 水平控制使用 `MoveTowards` 只调整速度的 x 分量；y 速度与摆荡产生的惯性不会被覆盖。
- 悠悠球是带 `Rigidbody2D` 和 `CircleCollider2D` 的实体，使用 `Continuous` 碰撞检测；不是射线抓钩。
- 命中点直接取第一个 `ContactPoint2D.point`，不搜索、吸附或修正支点。
- 发射时忽略悠悠球与玩家自己的碰撞，避免从角色中心生成后立刻自碰撞。这是实体发射所需的碰撞配置，不是移动限制。
- 未命中时按未缩放时间执行安全回收，避免慢动作延长玩家感知的最大飞行时间。

## 物理约束方案

固定时启用玩家身上的 `DistanceJoint2D`，`connectedBody = null`，以精确命中世界坐标作为 `connectedAnchor`。初始距离取固定瞬间玩家刚体中心到命中点的距离，启用 `maxDistanceOnly`，因此绳索只阻止玩家超过该半径，不会把松弛绳强行撑直。

固定和释放都不直接修改玩家速度。释放只禁用 Joint 并隐藏悠悠球，因此释放瞬间的线速度由 `Rigidbody2D` 自然保留。当前没有额外冲量或速度钳制。

## 子弹时间方案

开始瞄准时设置 `Time.timeScale`，同时将 `Time.fixedDeltaTime` 按相同比例缩放；结束瞄准时恢复两者。瞄准方向每帧从角色到鼠标世界坐标计算。蓄力和飞行超时均基于 `Time.unscaledTime`，因此不同时间倍率与帧率下的现实时间体验保持一致。

## 关键参数（首轮默认值）

- 地面速度：8；地面加速度：55；空中控制：0.45；重力倍率：3。
- 最小/最大投掷速度：12 / 36；蓄力时间：1.1 秒。
- 子弹时间倍率：0.2。
- 最大飞行时间：2.5 秒（未缩放时间）。
- 绳索连接双方碰撞：关闭。绳长在每次固定时由实际距离决定。

这些数值尚未经过正式试玩，只是便于首轮验证的起点。

## 已知 bug / 尚未解决

- 尚未实际验证脚本编译、场景生成结果和 Play Mode 行为。
- 固定动态刚体时支点不会随物体移动；当前灰盒范围没有动态平台。
- 屏幕中央的瞄准箭头是最低限度反馈，不跟随玩家。
- 角色接触斜面、墙角时的落地检测需要实际验证。
- 连续碰撞降低穿墙风险，但最大速度下的薄碰撞体仍需专项测试。

## 构建器修复记录

- 2026-09-16：首次在 Unity Editor 内执行场景构建时，`Arial.ttf` 在 Unity 2022.3 中已不再是有效内置字体，导致构建在 HUD 引用绑定前中断。已改用 `LegacyRuntime.ttf`，并让 `PrototypeHUD` 在引用不完整时禁用自身并输出一次明确错误，避免每帧刷 `NullReferenceException`。
